# Лимиты скиллов и файлов инструкций

Ограничения относятся к разным этапам работы агента: формату `SKILL.md`, начальному списку доступных скиллов,
загрузке выбранной инструкции и постоянным файлам проекта. Их нельзя сводить к одному «максимальному размеру
скилла». Значения ниже приведены по источникам, использованным в исходной статье 23.09.2026. Перед применением
конкретного числа следует открыть ссылку в разделе «Источники»: вендоры могут менять лимиты между версиями.

## Общий формат Agent Skills

Claude Code и Codex поддерживают [открытый формат Agent Skills](https://agentskills.io/specification).
Для переносимого скилла обязательны `name` и `description` в YAML-frontmatter. Имя каталога должно
совпадать с `name`.

| Элемент | Требование или рекомендация |
| --- | --- |
| `name` | 1-64 символа: строчные латинские буквы, цифры и дефисы. Без дефиса по краям и `--` |
| `description` | 1-1024 символа. Назначение скилла и условия его применения |
| `compatibility` | Необязательное поле до 500 символов для требований к продукту, пакетам, сети и окружению |
| Метаданные одного скилла в начальном списке | Около 100 токенов, прежде всего `name` и `description` |
| Основная часть `SKILL.md` | Рекомендуется менее 5000 токенов и менее 500 строк |
| Дополнительные файлы | Загружаются по необходимости, а не вместе со списком скиллов |
| Ссылки из `SKILL.md` | Рекомендуется один уровень вложенности без длинных цепочек справочников |

Поля `license`, `metadata` и экспериментальное `allowed-tools` необязательны. Поддержка `allowed-tools`
зависит от клиента. Подробный материал лучше выносить в `references/`, `assets/` и `scripts/`, оставляя в
`SKILL.md` карту процедуры. Сами эти файлы не становятся частью начального списка.

## Claude Code: локальные скиллы

Согласно [документации Claude Code](https://code.claude.com/docs/en/skills), локальный скилл допускает
более свободный frontmatter, чем общая спецификация. В нём все поля могут
отсутствовать: имя команды берётся из каталога, а запасным описанием становится первая непустая строка основной
части. Для переносимого скилла оба поля всё равно нужны. Если файл начинается с `# Документация модуля`, такое
запасное описание почти не помогает выбрать подходящую процедуру.

| Элемент | Ограничение или поведение |
| --- | --- |
| `description` и `when_to_use` в начальном списке | Общий текст обрезается после 1536 символов. Предел меняет `skillListingMaxDescChars` |
| Бюджет начального списка | По умолчанию до 1 % окна контекста. Долю меняет `skillListingBudgetFraction`, фиксированный бюджет в символах - `SLASH_COMMAND_TOOL_CHAR_BUDGET` |
| Переполнение списка | Имена остаются. Описания удаляются начиная с наименее часто вызываемых скиллов |
| `disable-model-invocation: true` | Описание не входит в начальный список до ручного вызова |
| Основная часть `SKILL.md` | Рекомендуется менее 500 строк. Подробности выносят в соседние файлы |
| После сжатия контекста | Сохраняются первые 5000 токенов последнего вызова каждого скилла |
| Общий бюджет после сжатия | 25 000 токенов. Сначала последние вызовы, ранние могут быть исключены |
| `allowed-tools` | Разрешения действуют в ходе вызова и сбрасываются после следующего сообщения пользователя |

Имя команды для скилла из `.claude/skills/` или `~/.claude/skills/` всегда определяется каталогом. Поле `name`
может менять отображаемое имя в списке, но не команду `/имя`. Если значения расходятся, в списке будет одно имя,
а запускаться скилл будет по другому. Поэтому совпадение требуется не только для переносимости, но и для
понятного ручного вызова.

Эти бюджеты описывают разные моменты: короткое описание доступно до выбора скилла, полный `SKILL.md` читается
при запуске, а после сжатия контекста сохраняется только часть истории его использования. Увеличение начального
бюджета не меняет автоматически лимит после сжатия.

## Платформа Claude

При загрузке скилла на платформу Claude поля `name` и `description` обязательны согласно
[рекомендациям Anthropic](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices).
Необязательность этих полей - особенность локального Claude Code, а не общее правило Anthropic.

| Элемент | Требование или рекомендация |
| --- | --- |
| `name` | 1-64 символа, строчные латинские буквы, цифры и дефисы. Без XML-тегов и зарезервированных слов `anthropic` и `claude` |
| `description` | Непустое поле до 1024 символов без XML-тегов. Описывает назначение и условия применения |
| Основная часть `SKILL.md` | Рекомендуется менее 500 строк |
| Справочный файл длиннее 100 строк | В начале рекомендуется оглавление |
| Ссылки на соседние файлы | Рекомендуется один уровень вложенности относительно `SKILL.md` |

Ограничения платформы важны, когда локальный скилл упаковывают для загрузки в Claude: файл, допустимый в
Claude Code за счёт запасного имени или описания, может не соответствовать требованиям загрузки.

## OpenAI Codex

Codex использует общие ограничения `name`, `description` и `compatibility`: 64, 1024 и 500 символов
соответственно. Собственные пределы Codex относятся прежде всего к начальному перечню скиллов, как
описано в [Build skills](https://learn.chatgpt.com/docs/build-skills).

| Элемент | Ограничение или поведение |
| --- | --- |
| Начальный список | Не более 2 % окна контекста. Если его размер неизвестен, предел 8000 символов |
| Содержимое списка | Имя, описание и путь к файлу скилла |
| Переполнение списка | Сначала сокращаются описания. Затем часть скиллов исключается, а Codex выводит предупреждение |
| Выбранный скилл | Предел начального списка не обрезает его `SKILL.md`: файл читается полностью |

Таким образом, короткое и различающее `description` влияет на обнаружение, но его предел не следует путать с
размером инструкции после выбора. Если скилл не попал в начальный список, проверяют бюджет и предупреждение,
а не только текст основной инструкции.

## Файлы инструкций проекта

По [документации Anthropic](https://code.claude.com/docs/en/memory), для Claude Code рекомендуется держать
каждый `CLAUDE.md` короче 200 строк. Импорт `@path` поддерживает до
четырёх последовательных переходов. Прямое чтение `AGENTS.md` заявлено начиная с версии 2.1.277, но может
быть недоступно в отдельных окружениях. Условия выбора файлов разобраны в
[статье об инструкциях проекта](../project-instructions/claude-code-and-codex.md).

По [документации OpenAI](https://learn.chatgpt.com/docs/agent-configuration/agents-md), Codex ограничивает
общий объём найденной цепочки параметром `project_doc_max_bytes`, по умолчанию 32 KiB.
В каждом каталоге включается не более одного непустого файла: сначала `AGENTS.override.md`, затем
`AGENTS.md`, после них имена из `project_doc_fallback_filenames`. Когда общий предел достигнут, следующие
файлы не добавляются.

Короткие постоянные инструкции удобнее проверять и поддерживать. Если они растут, тематические правила
размещают ближе к области применения или выносят в скилл, когда это самостоятельная процедура. Увеличивать
`project_doc_max_bytes` только ради редких справочных материалов не требуется: их можно загрузить по условию.
