# Инструкции проекта в Claude Code и OpenAI Codex

Файл инструкций сообщает агенту, как работать с конкретным репозиторием. В нём указывают команды сборки, запуска
и тестирования, устройство проекта, соглашения по коду, правила работы с ветками и критерии завершения задачи.
Для Claude Code основным файлом служит `CLAUDE.md`, для OpenAI Codex - `AGENTS.md`. Claude Code также может читать
`AGENTS.md`, но условия такого чтения зависят от версии, окружения и настройки Project instructions.

Инструкции входят в контекст модели и направляют её поведение, но не являются техническим запретом. Доступ к файлам
и командам ограничивают разрешениями, песочницей и, где поддерживается, хуками инструмента. Это важно при описании
правил безопасности: просьба в Markdown не заменяет настройку среды.

## Что писать в постоянных инструкциях

В файле должны находиться сведения, применимые ко многим задачам проекта. Например, требование использовать четыре
пробела для отступа относится к постоянным инструкциям. Последовательность создания окна - поиск шаблона, создание
файлов, регистрация и проверка - относится к отдельной процедуре и лучше оформляется как скилл.

Правила работают надёжнее, когда называют проверяемое действие или артефакт. «Соблюдай форматирование» не говорит,
что именно нужно сделать. «Используй отступ в четыре пробела и окончания строк LF» задаёт проверяемый результат.
Аналогично, вместо «Проверь изменения» стоит назвать проверку: «Перед завершением запусти сборку решения и убедись,
что ошибок компиляции нет».

Заголовки и списки разделяют команды, структуру проекта, стиль и проверку результата. Устаревшее правило следует
удалить или явно ограничить его область действия. Более близкий файл может оказаться позже в контексте, но это не
делает противоречие с общим правилом безопасным.

## Где находятся файлы

| Уровень | Claude Code | OpenAI Codex |
| --- | --- | --- |
| Пользователь | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` |
| Проект | `./CLAUDE.md` или `./.claude/CLAUDE.md` | `./AGENTS.md` |
| Личные настройки проекта | `./CLAUDE.local.md`, обычно вне Git | Отдельного личного файла нет. Временная замена - `AGENTS.override.md` |
| Подпапка | `CLAUDE.md` или `CLAUDE.local.md` | `AGENTS.md` или `AGENTS.override.md` |
| Организация | Управляемый `CLAUDE.md` | Политики среды. Проектный файл остаётся `AGENTS.md` |

`AGENTS.md` - открытое соглашение об имени Markdown-файла с инструкциями для агентов. Формат его разделов не
регламентирован. Файлы можно размещать и во вложенных каталогах. При этом
[Claude Code](https://code.claude.com/docs/en/memory)
и [Codex](https://developers.openai.com/codex/guides/agents-md) находят их по-разному.

## Как Claude Code собирает инструкции

Claude Code загружает уровни инструкций: управляемые правила организации, пользовательские настройки, проектные и
локальные файлы. Найденные `CLAUDE.md` остаются в контексте одновременно. Один файл не заменяет другой технически.
Если правила противоречат друг другу, результат может быть непредсказуемым.

При запуске Claude Code ищет `CLAUDE.md` и `CLAUDE.local.md` в рабочей директории и выше неё, вплоть до корня
файловой системы. Граница Git-репозитория этот поиск не останавливает. Инструкции из дочерней директории могут
подключиться позже, когда агент читает файлы в ней. Этим поиск инструкций отличается от поиска проектных скиллов.

Большой `CLAUDE.md` можно разделить на тематические файлы в `.claude/rules/`. Поле `paths` ограничивает правило
файлами, соответствующими указанным glob-шаблонам. Другой способ организации - импорт `@path/to/file` из
`CLAUDE.md`. Относительный путь считается от файла с импортом. Поддерживается до четырёх последовательных
переходов. Подключённый текст всё равно занимает контекст. Чтобы упомянуть путь без импорта, его заключают в
обратные кавычки: `@docs/code-style.md`.

## Как Codex строит цепочку

Codex собирает инструкции один раз при запуске сессии:

1. В `CODEX_HOME`, обычно `~/.codex`, выбирает `AGENTS.override.md` либо, если его нет, `AGENTS.md`.
2. От рабочей директории поднимается вверх до первого маркера корня проекта. По умолчанию это `.git`.
3. От найденного корня проходит к рабочей директории. В каждом каталоге берёт первый непустой файл:
   `AGENTS.override.md`, `AGENTS.md`, затем настроенное запасное имя.
4. Объединяет выбранные файлы от корня к рабочей директории. Ближайшее правило оказывается позже в тексте.

Если маркер не найден, Codex проверяет только текущую рабочую директорию. Набор маркеров задаётся параметром
`project_root_markers` в `config.toml`, например `[".git", ".hg", ".sl"]`. Пустой список делает корнем проекта
рабочую директорию. Codex не добавляет `AGENTS.md` из дочерней папки только потому, что позднее открыл в ней файл.
Чтобы применить вложенную инструкцию, новую сессию запускают из этой папки или указывают её через `--cd`.

Запасные имена и общий лимит цепочки также задают в `~/.codex/config.toml`:

```toml
project_doc_fallback_filenames = ["TEAM_GUIDE.md", ".agents.md"]
project_doc_max_bytes = 65536
```

В этом примере порядок выбора в каждом каталоге: `AGENTS.override.md`, `AGENTS.md`, `TEAM_GUIDE.md`,
`.agents.md`. Берётся только первый непустой файл. По умолчанию общий предел `project_doc_max_bytes` составляет
32 KiB. После его достижения следующие файлы не добавляются. Для Claude Code ориентир иной - менее 200 строк
на один `CLAUDE.md`. Числовые ограничения подробнее собраны в [отдельной статье](../agent-skills/limits.md).

В документации Codex не определён аналог импорта `@path` для `AGENTS.md`. Если нужен дополнительный документ,
инструкция должна прямо назвать файл и условие чтения, например: «Перед изменением публичного API прочитай
`docs/api-rules.md`». Такой способ подходит и для Claude Code.

## Когда Claude Code читает `AGENTS.md`

Начиная с Claude Code 2.1.277 прямое чтение `AGENTS.md` доступно в поддерживаемых окружениях. В стандартном режиме
`claude-md-or-agents-md` Claude Code выбирает `AGENTS.md` только если в рабочей директории и выше нет
`CLAUDE.md`, `.claude/CLAUDE.md` и `CLAUDE.local.md`. Пользовательский `~/.claude/CLAUDE.md`, управляемый файл
организации и `.claude/rules/` сами по себе этот выбор не отключают. Локальный `CLAUDE.local.md` отключает,
даже если он не хранится в репозитории.

| Ситуация | Что читает Claude Code в стандартном режиме |
| --- | --- |
| Есть только `AGENTS.md` | `AGENTS.md` |
| Есть `AGENTS.md` и проектный `CLAUDE.md` или `CLAUDE.local.md` | Файлы Claude, но не прямое содержимое `AGENTS.md` |
| `CLAUDE.md` импортирует `@AGENTS.md` | Оба содержимого через импорт |

В `/config` параметр Project instructions предлагает четыре режима: `claude-md-or-agents-md` (по умолчанию),
`claude-md-and-agents-md` (оба файла), `claude-md` (только файлы Claude) и `managed-only` (только управляемые
инструкции). При чтении обоих форматов в каждом каталоге сначала добавляется `CLAUDE.md`, затем `AGENTS.md`.
Настройку сохраняют в пользовательском `~/.claude/settings.json` или управляемых настройках:

```json
{
  "pluginConfigs": {
    "agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}
```

Проектные и локальные настройки Claude Code для этого параметра игнорируются, поэтому репозиторий не может
навязать такой режим всем участникам. Кроме того, прямое чтение может быть недоступно в версии ниже 2.1.277,
при работе через стороннего провайдера или отключённой телеметрии, в первой сессии после обновления, при
`disableAllHooks` или `allowManagedHooksOnly`, а также при отключённом встроенном плагине `agents-md`.
Эти случаи описаны в исходной статье и требуют повторной проверки в конкретном окружении.

## Один набор правил для двух вендоров

Для общего репозитория удобно хранить совместимые правила в `AGENTS.md`. Codex читает его напрямую. Короткий
`CLAUDE.md` подключает тот же текст и оставляет место для правил, относящихся только к Claude Code:

```markdown
@AGENTS.md

## Claude Code

Дополнительные правила, относящиеся только к Claude Code.
```

Такой вариант не зависит от настройки каждого участника. Режим `claude-md-and-agents-md` тоже позволяет читать
оба файла, но задаётся индивидуально. Копировать общие правила в два независимых файла не стоит: копии могут
разойтись.

Символическая ссылка `CLAUDE.md` на `AGENTS.md` возможна, но имеет ограничения. Инструменты Edit и Write могут
не изменять файл через ссылку. Для её создания в Windows могут требоваться права администратора или Developer
Mode. При отключённой поддержке ссылок Git может получить вместо неё обычный текстовый файл. Импорт в
`CLAUDE.md` обычно проще проверить и поддерживать.

## Как проверить загрузку

В Claude Code команда `/context` показывает раздел Memory files. При прямом чтении `AGENTS.md` также можно
проверить сообщение `AGENTS.md loaded` или спросить агента о действующих инструкциях. В Codex цепочку проверяют
из корня проекта командой:

```bash
codex --ask-for-approval never "Summarize the current instructions."
```

Для подпапки указывают рабочую директорию явно:

```bash
codex --cd <подпапка> --ask-for-approval never "Show which instruction files are active."
```

Если Codex показывает старую цепочку, нужна новая сессия в нужной директории: уже запущенный агент не
пересобирает её при каждом открытии файла. Итоговое различие простое: Claude Code может подключать вложенные
инструкции по мере работы с файлами, а Codex определяет цепочку при запуске.
